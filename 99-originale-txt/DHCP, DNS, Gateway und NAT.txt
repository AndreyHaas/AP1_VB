DHCP, DNS, Gateway и NAT
DHCP

DHCP автоматически выдаёт клиенту:

IP-адрес;
Subnetziëntmaske;
Default Gateway;
DNS-сервер.

Процесс называется DORA:

Discover → Offer → Request → Acknowledge

Если клиент получает адрес вида 169.254.x.x, это часто означает, что он не смог получить адрес от DHCP.

DNS

DNS преобразует имя в IP-адрес:

www.example.de → 93.184.216.34

Типичный признак проблемы DNS:

ping 1.1.1.1 работает
ping example.de не работает
Default Gateway

Gateway нужен для связи с другими сетями. Внутри собственной подсети устройства могут общаться напрямую, но для выхода в интернет нужен Router/Gateway.

NAT

Частные IP-адреса не маршрутизируются напрямую через интернет. NAT на роутере заменяет частный адрес публич/r адресом.

Благодаря NAT несколько устройств могут выходить в интернет через один публичный IPv4-адрес.

Важные диапазоны
Диапазон    Назначение
10.0.0.0/8  Private
172.16.0.0/12   Private: 172.16–172.31
192.168.0.0/16  Private
169.254.0.0/16  APIPA/Link-local
127.0.0.0/8 Loopback, например 127.0.0.1

Интернет

Публичный IP роутеру обычно предоставляет интернет-провайдер.

Правильный ответ — Default Gateway.

Если другие сотрудники имеют интернет, значит Router и NAT, скорее всего, работают. Проблема находится на конкретном компьютере. Если локальная сеть доступна, первым проверяем Gateway.

TCP и UDP
TCP
устанавливает соединение;
контролирует доставку;
сохраняет порядок данных;
потерянные пакеты отправляются повторно;
надёжнее, но создаёт дополнительную нагрузку.

Примеры: HTTPS, SSH, передача файлов.

UDP
не устанавливает соединение;
не гарантирует доставку и порядок;
имеет меньшую задержку.

Примеры: VoIP, видеотрансляции, DNS-запросы.
