Представь отправку посылки

Ты хочешь отправить в фирму сообщение:

«Покажите главную страницу сайта».

DNS — телефонная книга

Ты знаешь название фирмы:

example.de

Но не знаешь её адрес. DNS похож на телефонную книгу:

example.de → 93.184.216.34
Название фирмы → почтовый адрес здания

В сети таким адресом здания является IP.

IP — конечный адрес здания
Destination IP = 93.184.216.34

Он означает:

Посылка в конечном итоге должна попасть в это здание.

IP веб-сервера остаётся конечной целью на всём пути.

Port — отдел внутри здания

В одном здании работают разные отделы:

Port 443 → защищённый веб-сайт
Port 22  → SSH-администрирование
Port 25  → почтовый сервер

То есть:

IP   = адрес здания
Port = номер отдела внутри здания

Адрес 93.184.216.34:443 означает:

Доставить в здание 93.184.216.34, в отдел защищённых сайтов 443.

Router/Gateway — местное почтовое отделение

Твой компьютер не может напрямую передать посылку в другой город. Он сначала отдаёт её местному почтовому отделению — Default Gateway.

Компьютер → Gateway → интернет → веб-сервер

Router смотрит на конечный IP и решает, куда отправлять посылку дальше.

MAC — локальная этикетка доставки

На посылке фактически находятся две адресные информации:

Конечный адрес — IP веб-сервера.
Адрес следующей локальной остановки — MAC Gateway.

Можно представить посылку внутри транспортного контейнера:

Внешняя этикетка:
«Отнести ближайшему Gateway»
Destination MAC = MAC Gateway

Внутренняя посылка:
«Конечный получатель — веб-сервер»
Destination IP = IP веб-сервера

Почему компьютер не пишет MAC веб-сервера? Потому что веб-сервер находится далеко, в другой сети. Компьютер знает только, кому передать данные на следующем участке пути.

На каждом Router внешняя MAC-этикетка снимается и заменяется новой. Конечный IP внутри обычно остаётся прежним.

ARP — вопрос сотруднику справочной

Компьютер знает:

Gateway IP = 192.168.1.1

Но для локальной передачи ему нужен MAC. Поэтому он спрашивает:

Какой MAC принадлежит устройству с IP 192.168.1.1?

ARP отвечает:

192.168.1.1 → MAC Gateway

И только после этого компьютер может подписать локальную Ethernet-этикетку.

Switch — сортировщик внутри местного отделения

Switch смотрит только на локальную MAC-этикетку:

MAC Gateway находится за портом №5 — отправляю Frame туда.

Switch не доставляет посылку через интернет. Он только перемещает её внутри LAN.

TCP, TLS и HTTP

Теперь содержимое посылки.

TCP — заказная доставка

TCP похож на заказное письмо:

устанавливает связь;
нумерует части;
проверяет доставку;
повторно отправляет потерянные части.

Перед отправкой стороны подтверждают готовность:

SYN:     «Можно установить связь?»
SYN-ACK: «Да, я готов. А ты?»
ACK:     «Да, начинаем»
TLS — запертый сейф

TLS шифрует содержимое. Курьеры и почтовые отделения видят, куда доставлять данные, но не могут прочитать сообщение внутри.

HTTP — само сообщение

HTTP — это смысл сообщения:

GET /index.html

То есть:

Веб-сервер, пришли мне главную страницу.

Весь процесс одной историей

Когда ты вводишь https://example.de:

DNS находит IP фирмы.
Компьютер понимает, что фирма находится в другой сети.
ARP узнаёт MAC местного Gateway.
Switch передаёт данные Gateway.
Router отправляет их через интернет по IP.
TCP устанавливает надёжное соединение с портом 443.
TLS создаёт защищённый канал.
HTTP запрашивает страницу.

Коротко:

DNS → найти адрес
ARP → найти локальный MAC Gateway
TCP → установить надёжную доставку
TLS → зашифровать
HTTP → запросить страницу

Самая важная мысль:

MAC  = кому отдать на текущем участке
IP   = куда доставить в конечном итоге
Port = какому приложению отдать внутри компьютера

Что происходит при открытии HTTPS-сайта

Предположим, компьютер имеет:

IP:      192.168.10.25/24
Gateway: 192.168.10.1
DNS:     192.168.10.1

Пользователь вводит:

https://example.de
1. DNS-Auflösung

Компьютеру сначала нужен IP-адрес сайта:

example.de → DNS-запрос → IP-адрес сервера

Обычно запрос отправляется на:

Destination Port: 53/UDP

DNS относится к Layer 7, UDP — к Layer 4.

2. Проверка подсети

Компьютер сравнивает свою сеть с сетью сервера.

Если сайт находится за пределами локальной сети, пакет необходимо отправить через:

Default Gateway: 192.168.10.1
3. ARP-Auflösung

Чтобы передать Ethernet Frame роутеру, компьютер должен знать MAC-адрес Gateway.

Он отправляет Broadcast:

Кто имеет IP 192.168.10.1?

Router отвечает:

192.168.10.1 имеет MAC AA:BB:CC:DD:EE:FF

Важно: компьютер ищет MAC-адрес Gateway, а не MAC-адрес удалённого веб-сервера. MAC используется только внутри текущей локальной сети.

4. Создание данных

Получается такая вложенность:

Ethernet Frame
└── IP Packet
    └── TCP Segment
        └── TLS
            └── HTTP

Пример адресов:

Уровень	Source	Destination
Layer 2	MAC компьютера	MAC Gateway
Layer 3	IP компьютера	IP веб-сервера
Layer 4	Временный Port, например 52000	Port 443
5. Switch

Switch смотрит на Destination MAC и отправляет Frame в порт, за которым находится Router.

Switch → Layer 2 → MAC
6. Router и NAT

Router:

Удаляет старый Layer-2-заголовок.
Проверяет Destination IP.
Выбирает следующий маршрут.
При необходимости выполняет NAT.
Создаёт новый Ethernet Frame для следующего соединения.

На каждом участке меняются MAC-адреса. IP-адрес назначения обычно остаётся IP-адресом веб-сервера. При NAT частный Source IP заменяется публичным IP роутера.

7. TCP Three-Way Handshake

Перед передачей HTTPS-данных TCP устанавливает соединение:

Клиент → SYN     → Сервер
Клиент ← SYN-ACK ← Сервер
Клиент → ACK     → Сервер

После этого TCP-соединение установлено.

8. TLS Handshake

TLS обеспечивает шифрование:

сервер показывает Zertifikat;
клиент проверяет имя сайта, срок действия и доверенный центр сертификации;
стороны согласовывают алгоритмы;
создаются ключи сеанса.
9. HTTP

Теперь браузер отправляет внутри зашифрованного соединения:

GET / HTTP/1.1
Host: example.de

Сервер возвращает HTML, CSS, JavaScript и другие данные.
